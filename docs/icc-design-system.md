## 1. Концепции

### Концепция A — «Тихая консоль»

Нейтральная графитовая основа, три уровня поверхностей (основная, приподнятая,
утопленная). Единственный насыщенный цвет — синий акцент, и он означает только
управление и выбор. Все остальные цвета — семантика состояний (ok/warn/danger).
Разделение контента — границами и типографикой, не карточками. Исключение
(решение владельца): список пространств — сетка карточек с фиксированными
3 в ряд; карточка = заголовок-имя + метаданные (роль, даты), целиком ссылка,
без теней и анимаций сверх hover. Моноширинный
шрифт — только для технических значений. Плотные строки (32px), крупные зоны
только там, где читают текст, а не сканируют данные. Движение — только
функциональное (hover, поповер, модалка), 120–240мс.

Роль в отрасли: «спокойный инструмент» — то, во что смотрят 8 часов подряд;
статусы — единственные «цветные» элементы, поэтому взгляд мгновенно находит
проблему.

### Концепция B — «Терминальная плотность»

Почти чёрная основа, моноширинный шрифт шире, чем обычно (лейблы, значения,
кнопки). Строки 26–28px, разделители едва различимы, активная строка
подсвечивается, журналы и вывод команд — first-class во всех модулях. Акцент —
циан/зелёный. Характер «операторского пульта», очень высокая плотность.

### Сравнение

| Критерий | A «Тихая консоль» | B «Терминальная плотность» |
|---|---|---|
| Читаемость | Русские лейблы и формы — в системном sans 13px, кириллица в мелком mono читается хуже | Mono на лейблах снижает скорость сканирования таблиц; длинные русские тексты выглядят шумно |
| Плотность данных | 32px строки, компактные секции: ~15–17 строк на окне 800px | 26–28px строки: ~20 строк — выше, но ошибки чтения на мелком mono растут |
| Ежедневная работа | Спокойный фон, статусы не конкурируют с декором, глаза не устают | Напряжённее в длинных сессиях; эффектно в демо, утомительно каждый день |
| Соответствие desktop | Ровно тон системных утилит (Finder/NET-подобные плотные списки, DevTools) | Ближе к «хакерскому косплею»; рискует выглядеть темой, а не продуктом |

### Решение: A, с заимствованиями из B

- моно для **всех** технических значений (host, SHA, отпечатки, порты, версии);
- подсветка hover-строки и активной строки навигации;
- плотные строки таблиц (32px) и утопленный фон журналов;
- журнал — полноценный detail-вид (снимок/поллинг, «к низу», «показаны последние N»).

Причины отказа от B целиком: продукт русскоязычный и текстоёмкий (формы,
описания ошибок), статусы должны оставаться единственным цветовым сигналом,
а моно-везде забирает у них эту роль. Зелёный как акцент отклонён отдельно:
зелёный в ICC обязан означать «здорово», иначе ломается семантика состояний.

## 2. Токены и правила визуальной системы

### 2.1 Принципы

1. **Иерархия вместо декора.** Заголовок, действие, данные — три уровня
   важности, выраженные размером и цветом, а не рамками и тенями.
2. **Границы вместо карточек.** Карточка — только плавающий слой (модалка,
   поповер, меню). Секции страницы разделяются заголовком и границей.
3. **Статусные цвета эксклюзивны.** ok/warn/danger используются только для
   состояний. Декоративное их применение запрещено.
4. **Моно — только данные.** Моноширинно всё, что копируют или вставляют:
   `host`, SHA, `imageTag`, отпечаток, имя контейнера, журнал.
5. **Плотность по умолчанию.** 32px строки, 40px тулбары, 24px внутренние
   отступы панелей. Больше воздуха — только у форм и пустых состояний.
6. **Движение функционально.** Анимация сообщает о смене состояния, а не
   украшает. Уважает `prefers-reduced-motion`.
7. **Честные данные.** Нет данных в API — нет секции в UI. Неизвестный статус
   показывается как есть, нейтральным тоном. Секреты не показываются никогда.

### 2.3 Статусные цвета и правила использования

**Правило №1: статус = цвет + глиф + текст.** Цвет никогда не единственный
носитель смысла (дальтоники, grayscale-скриншот). Глифы — lucide 14px
(`circle-check`, `triangle-alert`, `octagon-x`, `info`, `circle-dashed`, `loader-2`
с вращением для активного процесса).

Маппинг домена (только реальные значения из API):

| Домен | Значение | Токен | Глиф |
|---|---|---|---|
| Server.status | ONLINE | ok | circle-check |
| | OFFLINE | neutral | circle-dashed |
| | PENDING | info | loader-2 (статично) |
| Agent.status | ACTIVE | ok | circle-check |
| | STALE | warn | triangle-alert |
| | FAILED | danger | octagon-x |
| | NOT_INSTALLED | neutral | circle-dashed |
| Deployment.status | QUEUED | neutral | circle-dashed |
| | RUNNING | info | loader-2 (вращение) |
| | SUCCESS | ok | circle-check |
| | FAILED | danger | octagon-x |
| | INTERRUPTED | warn | triangle-alert |
| Container.state | running | ok | circle-check |
| | exited / created | neutral | circle-dashed |
| | restarting / paused | warn | triangle-alert |
| | dead | danger | octagon-x |
| | прочее | neutral | текст как есть, без перевода |

Формы применения:
- **StatusBadge** (в таблицах, заголовках): фон `--*-muted`, текст `--*`, глиф,
  высота 20px, радиус 4px. Вариант `iconOnly` — глиф 13px в плашке 20×20,
  подпись статуса — в tooltip и aria-label; цвет по-прежнему не единственный
  носитель (глифы различны по форме). В карточках серверов статусов нет — они
  в шторке деталей (решения владельца 2026-10-11); `iconOnly` остаётся в
  витрине до нового потребителя.
- **Точка-индикатор** (в плотных подписях): 8px круг, только рядом с текстом.
- **Баннер/Callout** (ошибки операций): фон `--*-muted`, левая полоса 2px `--*`.
- Запрещено: красный текст «просто для внимания», зелёные кнопки, жёлтые ссылки.

### 2.4 Типографика

Шрифты (без новых зависимостей):

- UI: `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` — на macOS это
  SF Pro, на Windows — Segoe UI, на Linux — системный фолбэк; полная кириллица,
  нулевая загрузка, нативность.
- Данные: `ui-monospace, 'SF Mono', Menlo, Consolas, monospace`.

| Роль | Размер / вес | Где |
|---|---|---|
| Page title (h1) | 20 / 600 | Заголовок страницы, один на экран |
| Section title (h2) | 15 / 600 | Секции: «Серверы», «Последние деплои» |
| Panel title (h3) | 13 / 600 | Заголовки внутри панелей |
| Body | 13 / 400, line 1.45 | Основной текст, таблицы |
| Small | 12 / 400 | Вторичные подписи, ошибки полей, логи |
| Overline | 11 / 500, caps +0.06em | Группы навигации, заголовки колонок |
| Mono | размер среды, семья mono | Технические значения, журналы |

Правила: числа с `tabular-nums` всегда (класс `.tnum`); отрицательные значения
и большие числа не сокращать («1 048 576 байт», не «1MB» — точность важнее);
заголовки не капсить, капс — только оверлайны.

### 2.5 Сетка, отступы, размеры, границы, тени

- Базовая сетка 4px; шкала: 4 / 8 / 12 / 16 / 24 / 32 / 48.
- `--radius-xs: 4px` (бейджи, чипы), `--radius-sm: 6px` (кнопки, поля, строки
  навигации), `--radius-md: 8px` (панели, модалки, таблицы).
- Границы: 1px `--border` структурные; 1px `--border-strong` интерактивные.
  Границы не дублируются: у блока либо внешняя граница, либо фон-разделитель.
- Тени: только `--shadow-pop` у плавающих слоёв. Теней на «карточках» нет.
- Высоты: topbar 48, toolbar 40, строка таблицы **32** (Δ от 34), компактная
  строка 28, поле ввода 30 (sm 24), чип/бейдж 20–22. Sidebar 232. Шторка
  деталей (`--drawer-w`) — 360, на узких окнах — ≤92vw.
- Z-шкала: sticky-заголовки 10, поповеры 30, overlay 35, модалки 40, тосты 50.
- Контент страницы: паддинг 24, максимальная ширина 1200 (уже так).

### 2.6 Иерархия заголовков и действий

- На экране один h1. Секции — h2. Вложенные панели — h3. Ничего не пропускается.
- **Primary-действие — одно на регион** (страница/модалка): акцентная заливка.
  Пример: «Добавить сервер» на списке серверов.
- Secondary — кнопка с рамкой, для рядовых операций («Обновить», «Копировать»).
- Ghost — иконочные и строчные действия в тулбарах и таблицах.
- Danger — только разрушительное. Всегда через `ConfirmDialog` с повтором имени
  ресурса; в диалоге кнопка отмены — слева/фокус по умолчанию на отмене,
  разрушительная — с danger-заливкой.
- Опасное действие никогда не стоит вплотную к частому (например, «Перезапустить»
  не соседствует с «Открыть журнал» в одной иконочной группе строки).

### 2.7 Таблицы

- Заголовки колонок: Overline 11px muted, caps; sticky при скролле.
- Строки 32px; hover — фон `--bg-hover`; ссылка-имя — единственная навигация
  строки (остальное не кликабельно).
- Числа справа, `.tnum`. Моно — только для технических колонок (host, SHA, tag,
  отпечаток). Текстовые колонки — sans.
- Действия строки: максимум одна иконочная кнопка (24px, tooltip обязателен);
  появляется при hover и фокусе. Без «⋯»-меню, пока действий ≤ 1.
- Сортировка — `SortableTh` (см. §3.4): показывается только там, где сортировка
  честная — полный клиентский набор (контейнеры сервера) или серверный
  `sort`-параметр; на курсорных страницах списка не показывается до поддержки
  на бэкенде (сортировка одной страницы искажает порядок всего списка).
- Пагинация: списки с курсором — кнопка «Ещё» под таблицей с индикатором
  загрузки; список деплоев (лимит, без курсора) — подпись «Последние N».
- Множественное выделение строк отсутствует: bulk-операций в API нет.
- Состояния: загрузка — скелетон 6–8 строк внутри рамки (не пустая рамка);
  пусто — `EmptyState` с одним действием; ошибка — `ErrorState` в рамке с
  «Повторить»; обновление (refetch) — данные не исчезают, спиннер в тулбаре.
- Правила выше — для таблиц; карточная сетка (список серверов) — исключение
  владельца, см. 4.3: только личность сервера (ОС, имя, пользователь) и
  действие test; статусы — в шторке деталей; действия revealed по
  hover/focus-within, сетка не таблица.

### 2.8 Метрики

- Плитки метрик — ряд с вертикальными разделителями, **без карточек**.
- Анатомия: подпись Overline muted → значение 20/600 `.tnum` → единица 12 muted.
- Дельта/тренд не показывается: истории метрик в API нет.
- Обязательно время замера (`readAt` из stats) рядом с рядом плиток, muted.
- 4–6 плиток в ряд при 1280px; больше — перенос на второй ряд.

### 2.9 Логи и журналы

- Фон `--bg-inset`, mono 12, паддинг 12; перенос строк выключен (overflow-x),
  есть переключатель «перенос» для узких окон.
- `truncated: true` → баннер сверху панели: «Показаны последние N строк» (warn,
  not danger).
- Контейнерные логи — **снимок**: кнопка «Обновить», без автополлинга (follow
  в API нет). Таймстемпы muted; `stream: stderr` не красится красным (это не
  ошибка) — только muted-префикс потока.
- Логи деплоя — polling каждые 2с, пока `finished: false`; индикатор обновления
  в шапке панели; автоскролл к низу с «залипанием»: скролл вверх останавливает
  прилипание, появляется кнопка «К низу».
- Копирование целиком и выделенного — `CopyButton`.
- Журнал не размечается цветом по шагам: цвет остаётся за статусами.

### 2.10 Терминал

Полноценного терминала (exec) в API нет — в UI он не проектируется.
Визуальные правила на будущее: тот же `--bg-inset`, тот же mono 12, никакой
«зелёной матрицы»; курсор и промпт — нейтральные; вывод ошибок — `--danger`
только для реальных ошибок процесса.

### 2.11 Графики

В MVP графиков нет: stats — one-shot, истории метрик бэкенд не отдаёт.
Правила среза, который добавит историю (или клиентский спарклайн из нескольких
замеров при открытой странице):

- Линия 1.5px `--accent`, заливка `--accent` 15%, сетка отсутствует или
  `--border` 10%; min/max — подписи muted.
- Несколько серий: разные стили линии (сплошная/пунктир/точки) + прямые подписи,
  не только цвет.
- Живые графики — только с паузой обновления и стопом вне экрана (правило
  real-time: «живой» ярлык лишь при работающем источнике, со временем замера).
- Библиотека графиков подключается только вместе с реальным источником истории;
  до этого — inline SVG, без зависимостей.

### 2.12 Поведение состояний (сводно)

| Состояние | Правило |
|---|---|
| hover | только фон (`--bg-hover`), 120мс; без сдвигов и масштабирований |
| selected | навигация — фон `--accent-muted` + текст `--accent`; строка данных — фон `--bg-active`, без акцента |
| focus-visible | кольцо `--focus` на всех интерактивных элементах, никогда не убирается; цвет кольца не меняется под контекст |
| disabled | opacity .5, hover не работает, `cursor: default` |
| loading | кнопка — спиннер 14px вместо иконки и запрет повторного клика; список — скелетон; refetch — контент остаётся, спиннер в тулбаре |
| error поля | рамка `--danger`, текст ошибки 12px `--danger` под полем, helper меняется на ошибку |
| error операции | `Callout` danger с русским текстом и техническим кодом mono; 424 — с `errorCode`; 504 — «Операция не ответила вовремя» + «Повторить» |
| 429 (троттлинг) | `Callout` warn «Слишком часто, подождите N секунд»; кнопка операции блокируется с обратным отсчётом |
| success | без тостов в MVP: `Callout` ok на 4с или обновление статуса/данных; молчаливого успеха нет |
| disconnected | глобальный баннер (существует): warn-полоса под topbar, контент не блокируется |

### 3.9 Организация каталогов

```
src/
  ui/       примитивы: 1 компонент = tsx + css + spec, плоско, без подпапок
```

Правила: примитив в `ui/` не знает про API и не импортирует из `pages/`;
русские подписи статусов — только из `lib/statusMeta`; композиция с одним
потребителем живёт в своей feature-папке (`pages/`), в `ui/` переезжает при
втором потребителе.

### 3.10 План миграции (без одноразового переписывания)

1. **Токены — аддитивно** (сделано): новые переменные добавлены рядом со
   старыми. Единственные видимые дельты — строка таблицы 34→32 (§2.5) и
   подложка модалки → `--overlay`; обе зафиксированы в §2.
2. **Витрина `/kit`** (сделано): каждый компонент до первого потребителя
   появляется на витрине; запускаемый сценарий «Список серверов» — приёмка
   реального состава (сортировка, длинные имена, пустые значения, LoadMore).
3. **Первый реальный потребитель — срез 2 (серверы)**: PageHeader, Toolbar,
   Table + SortableTh, StatusBadge, Timestamp, IconButton, LoadMore
   подключаются на данных `GET workspaces/:id/servers`.
4. **Opportunistic refactors**: экраны среза 1 переводятся при касании, а не
   массово; первый пример сделан — `WorkspacesPage` использует `LoadMore`
   вместо собственной кнопки.
5. **Мёртвый код удаляется вместе с последним потребителем** (пример:
   `.ws-more` CSS удалён вместе с разметкой).
6. Legacy-долги вне касания не трогаются: «одна кнопка» не повод переписать
   страницу.

- Каждый примитив — colocated spec (vitest + testing-library, стиль

- `src/test/setup.ts` — общий cleanup RTL и шим `dialog.showModal` (jsdom);

- Приёмка среза — §5; обязательный браузерный чек витрины в обеих темах.

### 3.12 Governance

- **Владелец каталога — этот документ (§3)**: описание компонента и его
  spec-тесты меняются одним изменением; расхождение кода и §3 — баг.
- **Новый компонент** создаётся при сценарии повторного использования (2+
  потребителя) или под зафиксированный срез из IA-документа; «на будущее» не
  делается.
- **Новый вариант/токен**: сначала проверяются существующие; один декоративный
  случай не расширяет систему (пример: `danger-solid` добавлен только потому,
  что его требовал ConfirmDialog, а `danger` рамкой не читается как
  разрушительный).
- **Устаревание**: компонент без потребителей после среза — кандидат на
  удаление, не хранится «на всякий случай».
- **Живой реестр состояний** — витрина `/kit` (dev-only), она обновляется
  вместе с каталогом.

### 4.2 Dashboard (обзор пространства)

Данные: workspaces (имя), servers (агрегаты по статусам из списка), deployments
(последние, из list-эндпоинта без курсора). Ровно три горизонтальных блока:

1. Ряд метрик: «Серверы online/total», «Контейнеры running/stopped» — только
   если контейнеры доступны хотя бы с одного сервера, иначе блок не рисуется;
   «Деплои за сутки: успешных/всего» — MetricTile-и.
2. Секция «Серверы» — таблица первых 5 с колонками [Имя, Статус, Агент,
   Последняя проверка] + ссылка «Все серверы».
3. Секция «Последние деплои» — таблица первых 5 [Проект / Конфиг, Статус+шаг,
   Commit (mono, 8 символов), Начало] + «Все деплои».

Empty: без серверов — одна секция EmptyState «Добавить сервер» (это и есть
aha-moment по mvp-scope). Загрузка — скелетоны блоков. Ошибка одного блока —
ErrorState секции, остальные живут.

### 4.3 Server list

Данные: `GET workspaces/:id/servers` (курсор) + `GET servers/search` (Meilisearch,
дебаунс 300 мс; запрос и выдача — серверные). **Решение владельца 2026-10-11:
список — карточками, от 3 в ряд** (было: таблица). Сетка
`repeat(auto-fill, minmax(200px, 1fr))`: на минимальной ширине окна 960px
(960 − 232 сайдбар − 48 паддинг = 680) ложится ровно 3 колонки, шире — больше.

Карточка (`ul.sv-grid > li.sv-card`, stagger как у строк):

| Зона | Содержимое | Оформление |
|---|---|---|
| Шапка слева | `OsIcon` → имя → SSH-пользователь под именем | иконка 26px (тинт семейства); имя 700 strong, длинное — ellipsis (title с полным); пользователь 12 muted с ellipsis |
| Шапка справа | «Проверить» (test) | ghost-икона, появляется при hover/focus-within; busy — спиннер; disabled на время запроса и кулдауна |

Статусов и версии агента в карточке нет (решение владельца 2026-10-11 —
отменяет показ иконками), как и хоста, версии Docker и времени последней
проверки: всё это — в шторке деталей, карточка остаётся «паспортом» сервера.
ОС в бейдже — из `osName` сервера: заполняется `test`-флоу (hostnamectl →
uname -a, `os-probe.ts`); без пробы — «?» (не выдумываем). 429 от sshOps —
warn-Callout над сеткой с отсчётом. TOFU-модалка — как раньше (отпечаток +
«Доверять»). Пустая выдача поиска — EmptyState с текстом запроса.

**Клик по карточке открывает шторку деталей справа** (решение владельца
2026-10-11, см. 4.4). Карточка кликабельна целиком: `li.sv-card` держит
overlay-кнопку `button.sv-card-open` (inset 0, z-index 1) — доступна с
клавиатуры, имя «Открыть детали: {имя}»; «Проверить» (z-index 2) лежит выше
overlay и шторку не открывает. Пока шторка открыта, оболочка сужается на её
ширину (пуш-режим, §3.6) — сетка пересчитывает колонки под оставшуюся ширину.

**Мастер «Новый сервер» (решения владельца 2026-10-11):** `Modal` `wide` +
`dismissable=false` — крестика нет, закрытие только кнопкой «Отмена»; хост и
порт в одной строке (порт — узкая колонка 104px); аутентификация —
`SegmentedControl` (Пароль | Приватный ключ), не `Select`; пароль — с глазком
(`TextField.trailing`); secondary «Тестовое соединение» слева от
«Отмена»/«Сохранить» гоняет `test-connection` по данным формы: TOFU-блок
(отпечаток + «Доверять отпечатку») живёт прямо в модалке, подтверждённый
отпечаток уходит в `create` и пинится с первого дня; правка полей соединения
сбрасывает результат и пин.

### 4.4 Server details

```
Имя сервера  [ONLINE] [AGENT ACTIVE 0.1.0]      [Проверить SSH] [⋯ нет]
host:22 • sshUsername • KEY|PASSWORD            mono-строка мета
──────────────────────────────────────────────────────────────────────
Секция «Обзор» (DetailList):
  Хост / Порт / Пользователь / Тип аутентификации
  Отпечаток хоста (mono, CopyButton) / Docker (версия)
  Последняя проверка / Код последней ошибки (если есть)
  Блок агента: статус, версия, установлен когда, последний heartbeat
Секция «Контейнеры» (таблица):
  Имя | Образ (mono) | State (badge) | Status (как есть) | [↻ restart OWNER]
```

- TOFU-модалка: отпечаток mono крупно + предупреждение «Сверьте с хостом»,
  кнопка «Доверять» — единственная primary; повтор `test` после подтверждения.
- «Установить агента» — primary в блоке агента при NOT_INSTALLED (OWNER).
- 424 при действиях — Callout danger с `errorCode` mono и расшифровкой.
- Контейнеры: клик по строке → страница контейнера (лог-панель снимком,
  stats-плитки с `readAt`; restart — ConfirmDialog).
- Секреты отсутствуют на экране by design (эндпоинтов нет).

**Реализовано (2026-10-11): шторка деталей вместо страницы.** Клик по карточке
в списке открывает `Drawer` справа (`var(--drawer-w)`: 360, ≤92vw; пуш-режим —
оболочка сужается, §3.6): шапка — OsIcon + имя; `dl.sv-dl` — ОС («не
определена» при null), хост `host:port` (mono), пользователь SSH,
аутентификация («пароль»/«приватный ключ»), Docker, отпечаток хоста
(mono + CopyButton, если есть); `h3.sv-drawer-h` «Состояние» → статус/агент
**текстовыми** StatusBadge (в карточке статусов нет — шторка единственное
место, где они видны), «Последняя проверка» Timestamp, «Агент установлен»
(абсолютный), ошибка агента (mono). Внизу — `footer` шторки с primary
**«Подключиться»**: запускает тот же SSH-test, что «Проверить» на карточке
(TOFU-диалог как обычно), busy — спиннер, при кулдауне 429 заблокирована;
результат показывается Callout'ом внутри шторки (над сеткой не дублируется).
Шторка read-only во всём остальном: действия агента и контейнеры — за её
рамками. Эскиз выше — целевая страница.

### 4.5 Deploy details

```
Проект / Конфиг                    [SUCCESS]              [Запустить снова]
ref: main • commit a1b2c3d4 • image bios-deploy:019… • 4 мин 12 с
──────────────────────────────────────────────────────────────────────
StepProgress:  ✔ preflight  ✔ source  ✔ build  ✔ run
──────────────────────────────────────────────────────────────────────
Журнал (LogPanel, polling 2с пока RUNNING):
  шапка: «Журнал» • 12.4 КБ • [Обновить/Пауза] [К низу] [Копировать]
  тело: mono на --bg-inset
Ошибка (при FAILED): Callout danger — errorCode mono + русский текст
```

- `QUEUED`: StepProgress пуст, подпись «Ожидает исполнителя», журнал пуст.
- `RUNNING`: автообновление журнала, пауза доступна.
- `INTERRUPTED`: warn-Callout «Прерван рестартом панели», журнал сохраняется.
- «Запустить снова» — существующий POST deployments; при 409 показывается
  warn-Callout «Уже выполняется» (одна активная задача на конфиг).
- Отмены и расписаний нет — кнопок нет.

## 5. Критерии проверки визуальной согласованности

Проверяются на каждом срезе перед показом владельцу:

1. Нет hex/rgb вне `tokens.css` (поиск по `src/**` — только `var(--…)`).
2. Теней нет нигде, кроме поповеров/модалок/меню.
3. Каждый статус в UI: цвет + глиф + текст; скриншот в оттенках серого сохраняет
   различимость состояний.
4. Контраст основного текста ≥ 4.5:1 в обеих темах (проверить: text/bg,
   text-muted/bg-raised, status/bg-raised).
5. Строка таблицы 32±2px; на окне 1280×800 в списке видно ≥ 14 строк.
6. Моно — только у технических значений и журналов; ни один заголовок/кнопка
   не моно.
7. focus-visible виден на каждом интерактивном элементе; Tab-обход логичен;
   modal замыкает фокус.
8. hover-переходы ≤ 160мс, анимируются только цвет и прозрачность.
9. `prefers-reduced-motion`: спиннеры и пульсации статичны.
10. Один primary на регион; destructive — изолирован и только через ConfirmDialog
    с именем ресурса.
11. Каждый список/секция имеют loading / empty / error; refetch не опустошает
    контент.
12. 429 / 424 / 504 отображаются разными текстами (warn / danger+код / info);
    кнопка операции на время 429 блокируется.
13. Ни одного элемента интерфейса без источника в `docs/icc-api-matrix.md`;
    неизвестные статусы показываются как есть.
14. Окно на минимальном размере 960×600: ничего не перекрывается, тулбары не
    переносятся хаотично, горизонтальный скролл — только у таблиц/журналов.
15. Скроллбары стилизованы и видны в обеих темах; sticky-заголовки таблиц не
    перекрывают контент.
16. macOS / Windows / Linux: шрифты берутся из системных стеков, модификаторные
    подписи в UI соответствуют платформе (⌘ / Ctrl), даты и единицы — одни и те же.

## Приложение: что этот документ НЕ делает

- §3 описывает реализованный общий слой; экраны следуют §4 и подключают
